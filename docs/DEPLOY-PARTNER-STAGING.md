# Deploy partner staging — step by step

Use this guide to put the **full public website + live portals** on Render for your business partner to review. This URL is **not** yeanj.org — the live WordPress site stays untouched until you launch production.

**What gets deployed**

| Area | URL | Notes |
|------|-----|--------|
| Public website | `https://your-staging-url.onrender.com/` | Homepage, programs, enrollment, etc. |
| Portal hub | `/portal/` | Parent, staff, and admin entry |
| Parent portal | `/portal/parent/login/` | Real login required |
| Staff portal | `/portal/staff/login/` | Real login required |
| Portal admin | `/portal/admin/dashboard/` | Organization settings |

**What partners will NOT see**

- Yellow “Design preview mode” banner
- Green “Partially live mode” banner
- Demo login hints on login pages
- “Design preview (no login)” button on the portal hub

Those only appear when `PORTAL_PREVIEW_MODE=True` on your local machine.

---

## Before you start

1. **GitHub repo** — code should be at `https://github.com/jakeraj-bot/yea-website` (or your fork).
2. **Render account** — sign up at [render.com](https://render.com) if needed.
3. **Commit your changes** — push everything you want deployed to the `main` branch (or the branch Render will build from).

---

## Step 1 — Push code to GitHub

On your Mac, in the project folder:

```bash
cd ~/Projects/yea-website
git status
git add .
git commit -m "Partner staging: live portals and website updates"
git push origin main
```

Skip commit/push if your latest code is already on GitHub.

---

## Step 2 — Create the staging service on Render

### Option A — Blueprint (recommended, one click)

1. Log in to [Render Dashboard](https://dashboard.render.com).
2. Click **New → Blueprint**.
3. Connect your GitHub account if prompted.
4. Select the **yea-website** repository.
5. When asked which blueprint file to use, pick **`render-staging.yaml`** (not `render.yaml`).
6. Click **Apply**.

Render creates:

- Web service: `yea-website-staging`
- Database: `yea-db-staging` (separate from production)

### Option B — Manual duplicate

If you already have a production service:

1. **New → Web Service** from the same repo.
2. Name it `yea-website-staging`.
3. **Build command:** `./build.sh`
4. **Start command:** `gunicorn config.wsgi:application --bind 0.0.0.0:$PORT`
5. **New → PostgreSQL** named `yea-db-staging` and link `DATABASE_URL`.

---

## Step 3 — Set environment variables

In Render → **yea-website-staging** → **Environment**, confirm these values. Update the URL after Render assigns your hostname (often `yea-website-staging.onrender.com`).

| Variable | Value |
|----------|--------|
| `PYTHON_VERSION` | `3.12.7` |
| `DJANGO_DEBUG` | `False` |
| `PORTAL_PREVIEW_MODE` | **`False`** ← portals are live |
| `STAGING_SITE` | **`True`** ← hides dev banners, blocks Google |
| `DJANGO_ALLOWED_HOSTS` | `yea-website-staging.onrender.com,.onrender.com` |
| `SITE_URL` | `https://yea-website-staging.onrender.com` |
| `CSRF_TRUSTED_ORIGINS` | `https://yea-website-staging.onrender.com` |
| `CONTACT_EMAIL` | `info@yeanj.org` |
| `DEFAULT_FROM_EMAIL` | `noreply@yeanj.org` |
| `DJANGO_SECRET_KEY` | Auto-generated by Render (keep it) |
| `DATABASE_URL` | Linked from `yea-db-staging` |

Click **Save Changes**. Render redeploys automatically.

---

## Step 4 — Wait for the first deploy

1. Open **Logs** on the staging service.
2. Wait until you see the build finish and Gunicorn start.
3. Open your staging URL in a browser — you should see the **public homepage**.

If the deploy fails, check logs for missing env vars or migration errors.

---

## Step 5 — Seed portal data (required once)

The build runs migrations automatically, but **sample families, staff, units, and billing** come from a one-time seed command.

1. In Render → **yea-website-staging** → **Shell** (or **SSH**).
2. Run:

```bash
python manage.py seed_portal
```

3. Wait for “Portal seed complete” (or similar success output).
4. Optional sanity check:

```bash
python manage.py check
```

## Updating staging after changes

Whenever you push new code:

```bash
cd ~/Projects/yea-website
git add .
git commit -m "Describe your change"
git push origin main
```

Render auto-deploys from `main`. You **do not** need to run `seed_portal` again unless you reset the database.

To redeploy manually: Render → staging service → **Manual Deploy → Deploy latest commit**.

## Troubleshooting

| Problem | Fix |
|---------|-----|
| 502 / service sleeping | Render free/starter tiers spin down — first visit may take ~30s |
| CSRF error on forms | Set `SITE_URL` and `CSRF_TRUSTED_ORIGINS` to your exact Render URL |
| Attendance empty | Run `python manage.py seed_portal` in Render Shell |
| Yellow/green banners still show | Confirm `PORTAL_PREVIEW_MODE=False` and redeploy |
| “Design preview” on portal hub | Same — must be `PORTAL_PREVIEW_MODE=False` |
| Static files missing | Redeploy; `build.sh` runs `collectstatic` |

---

## When you are ready for yeanj.org

Do **not** point yeanj.org DNS at staging. For production launch, follow **`docs/LAUNCH-GUIDE.md`** and use **`render.yaml`** (production blueprint) with `STAGING_SITE=False`.

Keep staging running for QA until launch day.
